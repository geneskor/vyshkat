# ВышКат

ДЗ №1 по КПО. Консольное приложение для учёта транспорта и инвентаря кикшеринга «ВышКат».

## Что умеет программа

Можно добавлять транспорт в парк после проверки сервисным центром, хранить транспорт и другие вещи с инвентарными номерами, считать общее энергопотребление и получать список транспорта, который подходит новичкам.

Сейчас в программе есть три вида транспорта:

- `ElectricScooter` — электросамокат;
- `ElectricBike` — электровелосипед;
- `Bicycle` — обычный велосипед.

Из вещей есть:

- `Helmet` — шлем;
- `DockingStation` — док-станция;
- `ChargingCabinet` — зарядный шкаф.

Электросамокат, электровелосипед, док-станция и зарядный шкаф реализуют `EnergyConsumer`, потому что потребляют электроэнергию. Обычный велосипед и шлем его не реализуют.

Все объекты, которые ставятся на баланс, реализуют `InventoryItem` и имеют название и инвентарный номер.

## Запуск

Для проекта нужны Java 21 и Maven.

Запустить тесты:

```bash
mvn clean test
```

Само приложение запускается через:

```text
src/main/java/ru/hse/vyshkat/Main.java
```

## Структура

Код разделён на три основных пакета:

```text
ru.hse.vyshkat.domain
```

Здесь находится доменная модель: транспорт, вещи и интерфейсы `InventoryItem`, `EnergyConsumer` и `ServiceCenter`.

```text
ru.hse.vyshkat.service
```

Здесь находятся `FleetService` и `InventoryService`.

`FleetService` отвечает за приём транспорта в парк. Перед добавлением он вызывает `ServiceCenter` и добавляет транспорт только в случае успешного техосмотра.

`InventoryService` хранит объекты, находящиеся на балансе, и считает их суммарное суточное энергопотребление.

```text
ru.hse.vyshkat.config
```

Здесь находится `AppModule` с настройкой Guice.

## SOLID

Самый заметный принцип здесь — Dependency Inversion Principle.

`FleetService` не создаёт `DefaultServiceCenter` сам, а получает `ServiceCenter` через конструктор:

```java
public FleetService(ServiceCenter serviceCenter, InventoryService inventoryService)
```

А конкретная реализация задаётся в `AppModule`:

```java
bind(ServiceCenter.class).to(DefaultServiceCenter.class);
```

Благодаря этому в тестах вместо настоящего сервисного центра можно передать простую подмену:

```java
ServiceCenter serviceCenter = transport -> true;
```

или:

```java
ServiceCenter serviceCenter = transport -> false;
```

Также отдельно выделены интерфейсы `InventoryItem` и `EnergyConsumer`. Например, велосипед является инвентарным объектом, но не является потребителем энергии.

### Какой принцип сознательно ограничен

В случае с `InventoryService` принцип Single Responsibility применён не максимально строго. Сейчас этот сервис и хранит список инвентаря, и считает суммарное энергопотребление.

Можно было сделать для этого отдельные классы, но для такого небольшого проекта это только усложнило бы код. Поэтому эти операции оставлены в одном сервисе.

## Что будет при расширении

Если понадобится новый вид транспорта, достаточно унаследовать его от `Transport`. Если он электрический, дополнительно реализовать `EnergyConsumer`. `FleetService` при этом менять не нужно.

При добавлении сотрудников я бы сделал для них отдельную сущность, не связанную с `InventoryItem`, потому что по условию сотрудники не находятся на балансе.

Если появится склад запчастей, для него можно добавить отдельные сущности и сервис. Существующую модель транспорта для этого менять не потребуется.

## DI

В качестве DI-контейнера используется Google Guice.

Основные зависимости настраиваются в `AppModule`.

`InventoryService` зарегистрирован как singleton, потому что `Main` и `FleetService` должны работать с одним и тем же списком инвентаря.

Создание контейнера происходит в `Main`.

## Тесты

Тесты написаны на JUnit 5.

Сейчас есть:

- `FleetServiceTest` — приём и отклонение транспорта, подсчёт транспорта и правило для новичков;
- `InventoryServiceTest` — работа с инвентарём и подсчёт энергопотребления;
- `DomainModelTest` — основные свойства доменных объектов;
- `MainTest` — проверка консольного сценария приложения.

### Техосмотр и правило для новичков

В `FleetServiceTest` проверяется решение техосмотра: есть тесты как на успешную приёмку транспорта, так и на отказ.

`ServiceCenter` подменяется через зависимость, передаваемую в конструктор:

```java
ServiceCenter serviceCenter = transport -> true;
```

или:

```java
ServiceCenter serviceCenter = transport -> false;
```

В этом же тестовом классе проверяется правило для новичков. Отдельно проверено граничное значение `beginnerEase = 6`, при котором транспорт уже считается подходящим.

## Пример работы

При запуске программа создаёт несколько видов транспорта и вещей, принимает транспорт через сервисный центр, после чего выводит:

- количество принятого транспорта;
- суммарное суточное энергопотребление;
- транспорт, подходящий новичкам;
- весь инвентарь с названиями и инвентарными номерами.
